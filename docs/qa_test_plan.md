# QA Test Plan

## Automated

- Unit tests: level generation, canonical solution sum, adjacency, independent solver reachability, reducer, undo/reset, progress defaults and corrupted progress normalization.
- Unit tests also cover model validation: every board cell must match its grid index position, every cell value must be positive, board size must stay within the readable 4x4-6x6 release range, every level must have a released id, matching board size plus an in-board, non-empty, unique, adjacent solution path that sums to 56, and every `GameState` must keep selection shape, status, playable hint metadata and selected sum consistent.
- Solver tests verify every generated board can reach 56 without relying on the stored hint/solution path, and verify an impossible board returns no path.
- Solver and reducer tests cover current-selection-aware hints: a non-canonical but playable selected line gets the next reachable cell, while a dead-end line gets `HINT_REPAIR` with no highlighted cell and undo/reset guidance.
- Unit tests also cover exceeded-state lock: after sum exceeds 56, additional cell selection and hint do not mutate the path until undo/reset.
- Unit tests also cover reducer input hardening: coordinates outside the board are rejected without mutating the selection or crashing.
- Unit tests also cover immutable win state: after a level is won, selection, undo, reset and hint commands do not mutate the completed game state.
- Unit tests also cover invalid saved progress ids, corrupted completed-level CSV strings, last-level values and replayed completed levels so corrupted preferences cannot inflate progress, duplicate progress or continue to a non-existent level.
- Unit tests also cover optimistic completion progress: a new valid completion is recorded as the last played level, invalid completion ids are ignored and replaying an already-completed level remains idempotent.
- Unit tests also cover continue routing: the home primary action resumes the last selected incomplete level, falls back to the first incomplete level when that last level is complete, keeps a fresh first-level state as `Начать`, and switches to `Продолжить` after stopping on a later level.
- Unit tests also cover level navigation boundaries so invalid direct level requests clamp to available level ids, including sparse/reordered and duplicate level lists, instead of falling through unpredictably.
- Unit tests also cover home/progress next-level state for sparse/reordered and duplicate level lists so `Продолжить`, progress count, progress total, level-picker order and final-level result state use distinct sorted available level ids rather than raw list order or list size.
- Unit tests also cover final result copy: winning the highest-numbered level alone does not show `Все уровни пройдены`; that copy appears only when all available levels are complete, including the just-won current level.
- Unit tests also cover final result action fallback: after win, `Следующий уровень` is shown only when a higher available level id exists; otherwise the result panel shows `К уровням`; the next-level id is resolved from the authoritative `gameState.level` rather than a stale `currentLevel`.
- `tools/verify_release.py` gates haptic source markers so cell feedback remains tied to actual selected-path growth and victory feedback remains tied to a transition into `WON`, not arbitrary tap callbacks or restored screen state.
- Repository code now catches DataStore `IOException` during progress reads and emits default preferences; this protects first launch/home routing from local storage I/O failures. Full low-level filesystem fault injection remains out of scope for local unit tests.
- Instrumentation: Compose tests reset local DataStore state before each test, then check visible Russian product name, home progress semantics, accessible game board semantics, cell descriptions, game controls, settings options, About/privacy policy text, level completion, three-level progression, highest-level result fallback to `К уровням`, result replay after win with `Повторить`, game-back return to the entry screen, DataStore progress write and Activity recreation after win.
